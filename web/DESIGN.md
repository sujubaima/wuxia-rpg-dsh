# 武侠RPG 新 Web 界面设计（结构化面板层）

> 目标：聊天主界面文本体验**原样保留**；装备/武学/背包等"功能界面"升级为直调
> engine 的原生控件；右栏展示队伍状态。 coding agent 走 wuxia-rpg 技能完全零感知。

## 与现有 skill 的关系（红线）

- **不修改** `wuxia-rpg/` 任何文件（SKILL.md / references / scripts 原封）；GM 纪律（go/judge 两步、game-spec 自检、数据红线）原样生效，LLM 经由 `bash` 工具调脚本，web 不拦截不转包。
- 唯一改动是 `wuxia-rpg/scripts/engine.py` 的**增量字段**：所有 go/judge 返回顶层回显 `槽位`，删除存档返回额外带 `删除槽位`（为前端槽位同步服务；对 GM 流程零影响）。
- web/、agent/ 下的攻防（双后端 `LLM_BACKEND`、会话管理）不动。

## 布局（三栏，无抬头/无状态栏）

```
┌────────┬──────────────────────────────┬──────────┐
│  背包   │                              │ 时辰·位置 │
│  装备   │      主面板（随 TAB 切换)      │ 体力·金钱 │
│  武学   │  游历：现有聊天流一字不改       │──────────│
│  地图   │  其他：结构化控件卡             │  队伍      │
│  存档   │                              │ 角色HP/MP │
│  线索   │                              │          │
│  角色   │                              │          │
│  标题   │                              │          │
└────────┴──────────────────────────────┴──────────┘
```

- 游历 = 现在的聊天流（LLM 全量输出，抬头/界面块/叙事/战报一样不少）。
- 其余 TAB = 结构化控件，全部直调 engine。
- 战斗发生在游历文本里；战斗中右栏照常刷。

## 交互通道（按输入通道 + go 是否返回界面 两级路由）

| 通道 | 是否经过 LLM | 机制 |
|------|--------------|------|
| **主输入框打字**（任何时候） | **永远过** LLM | LLM 意图判断；agent 自己 go/judge；web 只看 SSE |
| **TAB 页控件点击** | **零 LLM** | 前端直调 `/api/engine` |
| 控件点击且 go **有界面** | 前端直接渲染返回 | 查询/配置/存档类 |
| 控件点击（如远行）go **无界面** | 后端自动下 `engine judge`（剧情由 GM 判定，此处 LLM 仍需介入）→ 再渲染 | 隐藏界面的动作 |

**过场模式开关：** 不加。保持 LLM 原输出。

## 槽位同步（前端持有，双通道带回）

- 前端用 `sessionStorage.wuxia_newui_slot` 记当前 slot，请求体永远显式带 `槽位`。
- 渲染到界面时检查返回：有 `槽位` 字段则更新（engine.go/judge 全量回显）；有 `删除槽位` 且 == 当前 slot → 清空、跳标题。
- 聊天通道（LLM）同样规则：引擎返回交给 LLM 后再渲染的界面同样走此逻辑（web 前端只看 SSE 文本不拆 JSON，不了结）。

## 状态栏数据源（右栏）

- **TAB 交互通道：** engine 返回字段直渲（队伍状态、时间、体力、金钱、位置等都在 go/judge 返回里）。
- **游历文本通道：** LLM 自己调 engine 时，其 tool 结果**在 LLM 内部被消费了**，web 只拿到 LLM 重写的中文文本。为不解析自由文本，**前端在每个 LLM 回合结束（SSE done）后静默调一次 `返回游戏` action**（查询类 go，零写盘零副作用），用返回的最新 exploration state 刷新右栏。顺带页面冷启动也用它拉一次。方案对比见后。

### 为什么不"拦截 LLM 的工具流结果"

- claude 后端：stream-json 包含 tool_result 事件、但 agent 后端 Agent 在 web 进程内（session.messages 里有原始 bash 结果）。可读，但识别"哪条 bash 是 engine 调用""引擎 go / judge 两轮如何选取回执""heredoc / 管道形态"深耦合。
- **选直调 `返回游戏`**（往返 ~50ms、纯查询）：和 LLM 完全解耦，拿到的是 judge 整体事务**落盘后**的真值，而拦截方案可能展示 go 后 judge 前的中间态。

## API

新增两个端点（server.py 内转发）：

```
POST /api/engine       调 engine.py（默认 go；{method:"judge"} 走 judge）
  请求体：原样 stdin JSON（{槽位, 行为, 当前剧情?, ...}）
  响应体：原样 stdout JSON（透传，仅 Content-Type 变）
  校验：仅查非空/非法 JSON；不查业务字段
POST /api/chat         （保留，原样）
```

### 路由 / 进程安全
- `GET /game` → 新界面 `game.html`；`/static/...` 走白名单 + 路径防穿越。
- 资源上限：请求体 2MB；engine 子进程 120s 超时；subprocess discard False 出绪 stderr 回 500。
- 不实现 `judge` 转发暂时：GM 仍走 LLM 内部（see 交互通道），前端 judge 入口 M2 后开。

## 错误与兜底

- engine 非零退出 → web 显示退出码 + stderr 尾部（500）
- engine 输出非 JSON → 报错原文（500）
- 前端 fetch 失败 → 该 TAB 显示错误红条，不影响其他 TAB 与游历
- 切 TAB 失败不污染右侧队伍栏

## 里程碑

| 阶段 | 范围 | 验证 |
|------|------|------|
| **M1 链路贯通** | `/api/engine` 转发层 + 三栏骨架（game.html + tab.js + 样式抽离） + 所有查询类 TAB（背包装备武学地图存档线索角色标题）能直拉 JSON 原样渲染 | 每个 TAB 点按钮出 JSON；slot 同步规则生效；老聊天页原样可用 |
| M2 控件化渲染 | 上述每 TAB 的返回字段映射为表格/勾选/下拉按钮控件，写完配置/购买/出售/精进/存档操作 | 装备穿上、武学装备、购买出售各走一遍 |
| M3 叙事区与队伍右栏联通 | 每 LLM 回合 done 后静默调`返回游戏`刷右侧；TAB 操作后本地灰色系统提示行进游历流；战斗时右栏随轮刷 | 打完一场战斗右栏始终同步 |
| M4 打磨 | 主题、八向罗盘地图、时辰徽标、快捷键 | 极顺畅体验对比 |

## 保留与切换

- `web/index.html` 一字不改地保留为**经典聊天 UI（/)**；
- 新界面是 `/game`，两页顶部都有对方入口链接；
- 前后端都可共存不断切换：sessionStorage 各自记 slot / sid，互不干扰。

## 维持现状的已有事实（不重复造）

- `engine.py` 的 `界面` 字段路由 17 种界面文档（渲染文层出不穷）→ 本方案取代的是"GM 把 JSON 抄成 markdown"的环节，不是 engine。
- 技能 SKILL.md 的所有"渲染文档路由/渲染纪律"**对 GM (LLM) 仍然生效**——前端只是多提供了一个*非 LLM* 的渲染路径。
- 网页聊天 SSE、agent/claude 双后端、tool 徽标、.sessions.json 全部保留。

## 附录 · M3.5 场景视图与战斗全屏（2026-07-30 已落地 v1）

改动面仅 `game.html`（`web.backup-*` 有改前备份），engine / skill 文档零改动。

- **游历场景视图**：中央抬头带承接地点时辰（右栏挪出，只留队伍）；`exploration-ui` 的 state 事件结构化渲染场景面板（剧情描写/变更飘字/要素 chips/八向罗盘）；罗盘点击 = 发 `前往XX` 聊天指令；LLM 聊天原文整体收进「足迹」折叠日志。配置类 go 的 exploration-ui 无剧情字段，只刷右栏不重绘场景。
- **战斗全屏**：`body.battle` 全屏接管——敌我阵卡 + 置顶行动预告横幅 + 右侧战报栏 + 底部控制台（武学四槽/物品/功能钮）。按钮从 v1 的“拼自然语言指令走 /api/chat”升级为**直驱**（见下条两步化）。界面数据：名单/血条解析 `玩家界面` 稳定文本；战斗伤害动画等精确数值取 `回合详情`。战前 exploration-battle-ui 弹操控方式浮层；终局出遮罩，引导处决答复。
- **战斗链路两步化（2026-07-30 已落，engine + battle.py 同改）**：
  - `engine go` 战斗操控（战斗-使用武学/物品/休息/逃跑/认输）**一律无界面**：机制后果落盘、`战报`（引擎原文）与新增 **`回合详情`**（结构化每回合明细）原样返回，底稿缓存 `battle_last.json`。
  - `engine judge` 新增 **战斗-推进** 条目：`战报文本`=GM 润色稿（缺省沿用引擎原文）、`回合详情`=照传 go 返回 → 打包 `界面=battle-ui`（不推进轮次）。战斗类 judge `当前剧情` 可传空。
  - 战斗-开始照旧 judge 产出 battle-ui（含开局运功的结构化条目）；战斗-结束/战后处置 judge 流程不变（先 战斗-推进 终局 battle-ui，再战后处置 exploration-ui）。
  - web `/api/engine` 新增 `method:"judge"`（服务端白名单仅 go/judge 转发，不解析业务字段）。
  - web 战斗控制台**直驱**：按钮调 go（无界面）→ judge `战斗-推进`（战报原样传给引擎）→ battle-ui；回合详情驱动卡面伤害飘字动画。战斗结束自动向 LLM 发隐藏摘要办战后处置。LLM 路径照旧：GM 判罚经 judge 战斗-推进 出 battle-ui，SSE 同入口渲染。
- **battle-end-ui（2026-07-30 已落，终局我方胜的处决裁定界面）**：终局 战斗操控 go / judge 战斗-推进 / AI 自动 judge 装配三处注入点，凡 `战局状态.状态`∈我方胜/敌方认输 → `界面=battle-end-ui`（含终局战报原文/回合详情/战果/**处决候选**=未逃走敌方）。新增 go 专属行为 `战斗-处决`（处置数组逐人杀/放，**只写回执记录、不落盘任何状态**，go 无界面）；玩家在 battle-end-ui 逐人裁定后 GM 叙事、judge 战后处置（处决/经验/战斗-结束/战利品一并）回 exploration-ui。敌方胜/平局维持原设计：GM 代敌方处置、judge 推进+战后处置。web：battle-end-ui 直接进战斗终局遮罩出逐人按钮，确认后经战斗-处决 go + 隐藏摘要给 LLM。
- **隐藏测试入口 `/static/fight-lab.html`（演武场，主界面无任何链接）**：专用测试档 slot「演武场主」（自动建/自动复用），双方全用预设角色组阵，**直接调 `engine judge 战斗-开始`**（不读玩家档、不经 LLM——仅此测试入口豁免；主路径游历→战斗仍严格走 LLM）。开庭返回暂存 `wuxia_pending_battle`，跳回 /game 经 routeUi 接管战斗界面；「收尾清档」一键删测试档零残留。

## 方案二随时可启

若 M3 实测"每回合后静默调返回游戏"的延迟不可接受，再打开"拦截 LLM 工具流"方案（Agent 后端读 session.messages 里 bash 原文 / claude 后端捡 stream-json 的 tool_result）做即时刷，直调`返回游戏`作兜底。M1 不过度设计。
