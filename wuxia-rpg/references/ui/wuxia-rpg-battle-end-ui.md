# battle-end-ui 渲染规范

终局状态为我方胜或敌方认输时，engine 返回 `界面=battle-end-ui`。本界面先呈现终局三层战报，再让玩家对所有未逃走的敌方角色逐人决定杀或放。

三层战报的润色、逐回合分段和数值格式完全遵循 [battle-ui.md](./wuxia-rpg-battle-ui.md)，且只使用首次返回的完整数据，禁止重跑战斗 action。

## 模板

终局战报之后追加：

━━ 模板开始 ━━
处决裁定（胜方处置败方，逐人决定）
- `{角色}`（{败阵/认输后的体态描写，气息尚存}）

请逐人答复（杀 / 放，可补充处置细节）：
━━ 模板结束 ━━

## 字段

- `战局状态`：应为我方胜或敌方认输。
- `战报`：按 battle-ui 的三层规范处理。
- `战果`：角色状态来源。
- `处决候选`：`[{名称,状态}]`，engine 已排除逃走者；须完整逐人展示，不自行增删。

处决前所有候选仍存活，只描写倒地、受制或认输，不预写死亡。

## 玩家答复与落盘

1. 收齐每名候选的杀/放决定；不得打包默认、诱导、劝阻或附议。
2. 调 go `战斗-处决`，`处置`数组逐人覆盖全部候选：`{角色,决定:杀|放,细节?}`。
3. 该 go 只记录答复，不落盘死亡、经验、战利品、体力或时间，也不返回界面。
4. 随后做战后 judge，一次性提交：
   - 与答复一致的死亡或放归结果；
   - go 返回的胜方经验，逃走者不发；
   - `战斗-结束`（自动体力-20、时间+8刻）；
   - 关系度、战利品及其他剧情后果。
5. judge `当前剧情`必填，返回 exploration-ui。

逃走者不在胜方手中，任何情况下不得处决。战利品不自动获得，须由玩家后续搜刮。
