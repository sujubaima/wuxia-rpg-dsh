# battle-ui 渲染规范

`战斗-开始`由 judge 进入 battle-ui。每轮战斗操控先 go 结算（无界面），GM 润色首次返回的完整战报，再 judge `战斗-推进` 打包为 battle-ui。终局我方胜或敌方认输改走 [battle-end-ui.md](./wuxia-rpg-battle-end-ui.md)。

## 三层战报

每个回合独立成段，回合间空一行：

1. **战局描述**：依据引擎结果文学化改写，武学与招式用【】；体现闪避、暴击、状态得失、增伤、反制与恢复改写。关键回合精细润色，普通命中可简写，但禁止原样粘贴引擎草稿。
2. **对白（可选）**：另起一行，注明说话人及神态/动作，契合人设、频率克制。
3. **数值变化**：引擎数值完整保留，一行一条，格式为 `` `{角色} {属性} {原值→新值}` ``；状态写「获得N回合【状态】」「失去【状态】」「时序±N」，不附来源后缀。

第一层可自然写伤害/恢复数字，但不用箭头报告式。状态效果须写清归属；心法长效状态显示心法名。多回合严禁合并成一段，AI 回合也不得压缩省略。

### 开局运功

对阵概览原样保留。其后按三层结构润色运功回合：文学化运功描写、可选对白、状态获得数值行；长效状态不写持续时间。

## 玩家回合

进行中且轮到受控角色时，engine 返回 `玩家界面`，必须原样呈现，包括状态表、行动预告、可用武学、可用物品和指令提示。禁止改写可用性、目标范围或提供战术建议。

玩家指令：

- `武学 [技能] [目标]`：出招，可分步补参数。
- `使用 [物品] [目标]`：丹药默认自己、道具默认首个敌方，占一回合。
- `休息`：恢复10%最大内力，不回气血。
- `查看人物信息`：不耗回合。
- `逃跑`：按本场允许逃跑设置进行个人判定。
- `认输`：整队判负，不掷骰、不耗回合。

无法识别、缺参数或不可执行时，说明原因并原样重绘完整玩家界面，不推进战斗。

## 逃跑与认输

- 是否允许逃跑由开战时确定，整场不变。
- 不允许：提示「无法逃跑——此战不容脱身」，重绘玩家界面，不耗回合。
- 成功：该角色逃走并退出本场，不受伤、不离队、不得经验，战斗由其余人继续；该方全员退出时判负。
- 失败：提示未能脱身，消耗本回合，战斗继续。
- 认输：玩家方整队判负，进入我方失败终局处理。

## 非我方胜终局

`战局状态.状态`为我方败、我方认输或平局时：

1. judge `战斗-推进`渲染完整终局 battle-ui，三层战报规则不变。
2. 我方败/认输：GM 据敌方立场、动机和关系度逐人决定未逃走我方角色的处置；逃走者不得处决。非必杀可改为俘虏、掠财、勒索、羞辱或重伤弃置。
3. 平局：双方存活，不处决、不发经验，由剧情合理收场。
4. 随后战后 judge 一次落盘死亡、关系度及其他后果，并带 `战斗-结束`；败方和平局不发经验，返回 exploration-ui。

我方胜/敌方认输不在本文件处理，按 [battle-end-ui.md](./wuxia-rpg-battle-end-ui.md)等待玩家逐人杀放。

## 返回字段

- `战局状态`：状态、回合数、我方、敌方。
- `战报`：三层战报原文；GM只改写文学层与排版，不改数值。
- `玩家界面`：进行中轮到玩家时存在，原样输出。
- `战果`：终局角色状态（存活/败阵/逃走）。

## 红线

- 一次 go 返回的 `战报`必须完整取用；禁止截断，也禁止为补全文本重调战斗 action，重复调用会多推进回合。
- 战斗状态非进行中时必须完成对应终局与战后处置，不得直接跳回 exploration-ui。
- 战报直接输出为 Markdown，不包代码围栏，不加分隔线或界面外分析。
