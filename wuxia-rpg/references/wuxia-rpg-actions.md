# 行为与状态变更契约

本文件是 `行为` 数组参数的唯一权威来源。意图路由见 [SKILL.md](../SKILL.md)，推演原则见 [wuxia-rpg-exploration-rules.md](./wuxia-rpg-exploration-rules.md)。

- **go 行为**：玩家主动指令；行为类通常消耗体力/时间，配置与查询类不消耗。
- **空行为数组**：所有行动均因已确定的剧情约束无法执行时传 `"行为":[]`；不消耗体力或时间、不产生机械事件，随后必须 judge 叙述受阻结果。
- **judge 条目**：GM 推演结果，包括状态变更及战斗触发/开始/推进。

时间统一用刻：1时辰=8刻，1天=96刻。

## go：大世界行为

| 类型 | 参数 | engine 语义 |
|------|------|-------------|
| `休息` | `等级`(露宿/简朴/中等/奢华),`时长`,`免费`(必传bool) | 露宿每时辰回10体力；简朴/中等/奢华每刻4/5/6钱，每时辰回15/20/25体力及上限15%/20%/25%气血内力。免费时费用0；恢复由 go 完成，judge 不重复 |
| `远行（徒步）` | `目的地` | 区域内按登记场景图寻路；每边消耗5体力、4刻。跨区域、不连通、原地均报错 |
| `远行（舟车）` | `目的地`(可省) | 无目的地打开远行界面；有目的地须位于驿站，扣路线费用、推进天数、补满体力并抵达 |
| `使用物品` | `物品`,`目标`(默认主控) | 大世界统一入口，扣1体力1刻；engine 按子类型处理秘籍、技艺书、食物等，并校验适用场合 |
| `购买` | `卖家`,`物品`,`数量`,`价格`,`商人`,`买家`(默认主控),`标签` | 无物品打开购买界面；有物品扣2体力2刻、铜钱并入栏。`商人`表示本次是否货架交易 |
| `出售` | `买家`,`物品`,`数量`,`价格`,`商人`,`卖家`(默认主控) | 无物品打开出售界面；有物品扣2体力2刻、物品出栏并加铜钱 |
| `赠与物品` | `物品`,`受赠者`,`数量`(默认1),`赠送者`(默认主控) | 扣1体力1刻并转移物品；受赠者须已落盘，随后 judge 承接反应/关系度 |
| `遣散` | `角色` | 遣散费=一级属性和×10；铜钱不足则关系度-20并离队，随后 judge 写剧情善后 |
| `交谈观察` | `目标` | 与指定人物交谈或观察指定对象，扣1体力、1刻；剧情及数据后果由 judge 承载 |
| `搜查翻找` | `目标`(可选) | 搜查场景、翻动物件或寻找隐藏内容，扣2体力、2刻；发现结果由 judge 承载 |
| `其他行为` | `描述` | 无法归类的杂项动作，扣4体力、2刻，后续由 judge 承载 |
| `攻击` | `目标`(可选) | 扣1体力、1刻；是否触战由 GM 推演，触战经 judge `战斗-触发` |

## go：配置、查询与系统行为

| 类型 | 参数 | 语义 |
|------|------|------|
| `配置装备` | `角色`,`操作`(穿/脱),`槽位`,`物品`(穿时) | 无操作打开装备配置；有操作穿脱五类槽位 |
| `配置物品` | `角色`,`操作`(装/卸/换),`物品`,`目标物品`(换时),`携带物品`[](≤4类) | 配置战斗携带消耗品 |
| `配置武学` | `角色`,`操作`(装/卸/换),`武学`,`目标武学`(换时),`携带技能`[](≤4),`运转心法` | 配置已习得主动武学或心法 |
| `武学精进` | `角色`,`武学`,`操作`(精进) | 无武学列出可选武学；有武学无操作查看十境表；精进消耗经验升一境。秘籍研读走 `使用物品` |
| `角色信息` | `角色` | 角色必填 |
| `查看背包` | `筛选类型`,`筛选子类型`,`适用场合`(可选) | 类型/子类型可传单值或数组 |
| `查看地图` | `当前场景`(可选) | 据当前位置展示区域地图；必要时用参数补全并持久化当前场景 |
| `查看线索` | — | 列出当前已获线索及进展 |
| `武学列表` | `角色` | 返回该角色全部主动武学与心法；角色必填 |
| `战斗-使用武学` | `武学`,`目标` | 推进战斗一轮；go 无界面，随后 judge `战斗-推进` |
| `战斗-使用物品` | `物品`,`目标` | 同上 |
| `战斗-休息` | — | 同上 |
| `战斗-逃跑` | — | 个人逃跑判定；同上 |
| `战斗-认输` | — | 认输方整队判负；同上 |
| `战斗-处决` | `处置`[]：`{角色,决定:杀\|放,细节?}` | 我方胜后逐人记录处决答复，不落盘任何状态；go 无界面 |
| `标题-操作` | `操作`,`创建草稿`及步骤参数 | 无状态驱动标题主页、全槽位读档和三步创建；具体操作见 title-ui 文档 |
| `创建角色` | `角色`完整dict，或`创建草稿`+`初始武学` | 顶层`槽位`须用`开始游戏.next_slot`；冲突返回最新编号；完整dict过严格schema校验（字段名/值域错误当场打回）；成功后 judge 写开场与首份存档 |
| `保存游戏` | `标签`(必填),`经历概括`(可选) | 手动存档，标签不得为空 |
| `加载存档` | `目标` | 目标可为 File_N、时间戳、label或子串 |
| `删除存档` | `目标`(可选),`槽位`(可选) | 有目标删单个存档点，无目标删整个角色档；调用前必须确认 |
| `存档列表` | — | 当前 slot 的存档列表 |
| `开始游戏` | — | 全部 slot 的存档列表及`next_slot` |
| `非法指令` | `提示` | 不结算、不落盘、不推进 |
| `返回游戏` | — | 回放当前游历界面 |

## scene-prepare：场景规划

仅在 go 已完成、等待 judge 时使用；`场景`数组可混合以下操作，只预校验、不改正式地图：

- `登记`：`区域`,`场景`,`方位出口?`,`功能类型?`,`功能NPC?`；新增地点或给孤点补出口。
- `隔离`：`区域`,`场景`；删除该地点全部连接（置为孤点，地点保留）。
- `重连`：`区域`,`场景`,`方位出口`；先隔离再以新出口重登。

同轮后一次成功调用整体覆盖旧批次；空数组清除草稿。judge 用一次 `场景-采用草稿` 整批采用；失败保留，成功或读档后清理。

## quest-prepare：即兴线索蓝图

仅在 go 已完成、等待 judge 时使用；先完成影响剧情的 check/random-event。`任务`为非空数组，可混合创建、扩展和关闭；它只预校验，不改正式状态。

```json
{"槽位":1,"任务":[{"操作":"创建","蓝图":{...},"隐藏":false},{"操作":"扩展","蓝图":{"名称":"账册疑云","扩展点":"follow-up","版本":2,"起始节点":["trace-seal"],"节点":[...]}},{"操作":"关闭","蓝图":{"名称":"账册疑云","节点":"follow-up","描述":"此案无从再查，就此搁下。"}}]}
```

同一轮后一次成功 prepare 整体覆盖旧批次；失败不覆盖。judge 可按线索名称采用其中一个或多个；judge 失败保留批次，成功或加载存档后清理。

**增量生长**：即兴线索逐级生长，每次只设计当前一级——

- 创建：只允许单一初始节点加一级后继（一级后继不得再带后继节点，且各须为终局或扩展点；分支数不限），至少含一个 `扩展点: true` 节点；
- 扩展：只在扩展点下挂一级新节点（前置须且仅须该扩展点、不带后继，各须为终局或扩展点；分支数不限）；
- 关闭：强关一个未激活扩展点、不增后继（该方向无继续推演必要时用）。蓝图仅 `名称`、`节点`、`描述`（必填，玩家可见的关闭文案）；任务须进行中，扩展点须未激活、未关闭。

## judge 顶层字段

```json
{"槽位":1,"行为":[...],"当前剧情":"...","场景要素":[...],"提及地点":[...],"经历概括":"..."}
```

- `当前剧情`必填，作为返回的 `剧情描写` 原样使用；战斗推进轮可空。
- `场景要素`非战斗 judge 必填非空（战斗类 judge 豁免）：缺省或空数组会被打回，场景无变化也须重报现状，且以状态变更落定后的新场景为准。维持3～5项：`{主体,描写?,特殊指令?}`；每项 `描写` 不超过30字。`特殊指令`仅可放在当前场景绑定的功能 NPC 要素上，普通 NPC、物件和环境要素不得携带；须严格匹配场景功能：驿站 `远行（舟车）`、店铺 `购买`和`出售`、客栈 `投宿`，不得添加交谈、搜查等普通行为。格式为 `[{名称,可用}]`，`可用`为 bool；功能 NPC 的`主体`以绑定名称开头即可，如「驿丞」「驿丞陈四」。死亡角色不得作为要素主体（engine 打回）；尸体/遗物/旧地等以「角色名+的+…」表述放行，名称可写入描写。玩家主控同样不得作为要素主体（engine 打回，主控状态由队伍面板承载）；随身物件以「角色名+的+…」表述放行。
- `提及地点`必填（可为空数组，不得缺省）：本轮叙事新提及、玩家可前往的「区域·场景」全名（如 苏州·玄妙观）。裸场景名会被打回。已登记或本轮草稿已登记者通过；未登记则先 `scene-prepare`，不可达/无需涉足则移出列表。
- `经历概括`可选，传精简后的全量概括以覆盖旧值。

## judge：战斗条目

| 类型 | 参数 | 语义 |
|------|------|------|
| `战斗-触发` | `我方`[],`敌方`[],`允许逃跑` | 不开战，仅确认参战方与操控方式；参战者须已有角色记录，自创者可在同轮先`写角色` |
| `战斗-开始` | 上述三项+`操控方式`(玩家角色/我方全员/AI自动) | 启动战斗；战斗本身不推进大世界时间 |
| `战斗-推进` | `回合详情`(可选) | 打包上一轮 go 缓存的规范战报；不得传 `战报文本`，`回合详情`仅作结构化兼容 |

## judge：状态变更

每项格式为 `{"类型":...,"操作":...,"角色":...,...}`。

| 类型 | 操作与参数 |
|------|------------|
| 铜钱 / 经验 | `加/减`,`值` |
| 关系度 | `加/减`,`角色`,`值` |
| 物品 | `增/减`,`名`,`数量`(默认1) |
| 使用物品 | `物品`,`目标`；不自动扣体力/时间，需要时另传条目 |
| 装备 | `穿/脱`,`名`,`槽位` |
| 携带技能 / 携带物品 | `设`,`名列表`(≤4) |
| 运转心法 | `设`,`名`；卸下填「无」 |
| 技艺 | `加/减`,`名`,`值` |
| 在队 | `入/离`；离队可带`原因` |
| 气血 / 内力 / 体力 | `设/加`,`值` |
| 时间 | `加`,`值`(刻) |
| 死亡 | `处决`,`角色` |
| 写角色 | `角色`完整dict；重名则整轮回滚，自创龙套可带`持久化:false`；字段须过schema校验，必填字段、键名与值域见 [wuxia-rpg-data-schema.md](./wuxia-rpg-data-schema.md) 模板，派生字段（气血/内力/二级属性）不传 |
| 抵达 | `位置`；仅用于被押送、传送等非远行式到达；须为已登记的「区域·场景」（同轮先登记亦可），未登记报错 |
| 武学 | `精进/习得`,`名`；剧情性授武用，秘籍研读不用 |
| 战斗-结束 | 无参数；自动体力-20、时间+8刻，战后 judge 必带 |
| 场景-采用草稿 | 无参数；采用当前 scene-prepare 整批规划，在本次 judge 中重新校验并原子提交；登记成功自动写机械事实 `scene:区域·场景.exists@world` |
| 线索-采用草稿 | `名称列表`（非空、无重复）；采用当前批次中的一个或多个任务，并在本次 judge 中重新校验后原子提交 |
| 线索-发现 | `名称`；将已创建的隐藏线索转为进行中 |
| 线索-创建 | `任务`蓝图,`隐藏?`；兼容/内部入口，GM 即兴创建主路径使用 `quest-prepare` |
| 线索-扩展 | `名称`,`扩展点`,`版本`,`起始节点`,`节点`,`事实定义?`；兼容/内部入口，GM 主路径使用 `quest-prepare` |
| 事实 / 事实-写入 | `事实`,`值`,`状态?`,`来源?`,`证据?`；写入已注册事实并自动归约相关线索 |
| 事实-修订 | 同上，另须`原因`；仅用于调包、误认揭示或明确设定修订 |

### 线索蓝图

创建时将完整蓝图交给 `quest-prepare`：

```json
{
  "槽位": 1,
  "任务": [
    {
      "操作": "创建",
      "隐藏": false,
      "蓝图": {
        "名称": "账册疑云",
    "版本": 1,
    "引子": "一册旧账牵出疑云。",
    "隐藏目标": "确认账册真伪",
    "事实定义": [
      {"事实键": "item:ledger_001.authenticity@world", "描述": "账册的真实真伪", "值类型": "enum", "可选值": ["authentic", "forged"]},
      {"事实键": "item:ledger_001.missing_pages@world", "描述": "账册是否缺页", "值类型": "bool"}
    ],
    "起始节点": ["heard"],
    "节点": [
      {"节点ID": "heard", "完成条件": {}, "完成摘要": "得知账册之谜。", "关闭条件": null, "关闭描述": null, "后继节点": ["authentic", "forged", "follow-up"]},
      {"节点ID": "authentic", "前置节点": ["heard"], "完成条件": {"fact": "item:ledger_001.authenticity@world", "eq": "authentic"}, "完成摘要": "确认账册是真品。", "关闭条件": null, "关闭描述": null, "终局": true},
      {"节点ID": "forged", "前置节点": ["heard"], "完成条件": {"fact": "item:ledger_001.authenticity@world", "eq": "forged"}, "完成摘要": "查明账册系伪造。", "关闭条件": null, "关闭描述": null, "终局": true},
      {"节点ID": "follow-up", "前置节点": ["heard"], "完成条件": {"fact": "item:ledger_001.missing_pages@world", "eq": true}, "完成摘要": "翻查发现账册缺页，须追查印章来源。", "关闭条件": null, "关闭描述": null, "扩展点": true}
        ]
      }
    }
  ]
}
```

成功后在最终 judge 按线索名称采用：

```json
{"类型":"线索-采用草稿","名称列表":["账册疑云"]}
```

节点可用字段：`节点ID`、`前置节点`、`汇合规则`(`all/any`)、`完成条件`、`完成摘要`、`关闭条件`、`关闭描述`、`后继节点`、`玩家可见`、`扩展点`、`终局`(`true`=定局节点，值无优劣语义)、`效果`、`奖励`。每个节点必须显式提供关闭两字段：不用时均为 `null`；启用时传条件对象和非空描述；`关闭条件:{}` 表示到达后无条件关闭该支路。含状态变化的奖励格式为：

```json
{"奖励ID":"ledger:forged:reward","描述":"经验500","状态变更":[{"类型":"经验","操作":"加","角色":"玩家","值":500}]}
```

事实定义必须含一句非空 `描述`，用于 GM 候选提示；`值类型` 支持 `bool/enum/number/string/entity/set`，可选 `互斥组`。叙事事实默认只能显式修订。`enum` 的各可选值必须在剧情逻辑下互斥（任一时刻至多一个成立）；可能同时成立的维度须拆成多个事实（如"处置结果"与"是否下毒"是两个事实），否则分支条件会互相掐死，画出拓扑上不可达的蓝图。

条件 DSL：

- 事实：`{"fact":"事实键","eq":值}`；比较符还支持 `ne/in/exists/gt/gte/lt/lte/status`；
- 节点：`{"node":"节点ID","completed":true}`；
- 组合：`{"all":[...]}`、`{"any":[...]}`、`{"not":{...}}`；
- 空对象 `{}` 表示前置满足后立即完成；用于关闭条件时表示到达后立即关闭该支路。

关闭支路示例：

```json
{"节点ID":"find-witness","前置节点":["heard"],"完成条件":{"fact":"character:witness.found@world","eq":true},"完成摘要":"找到了证人。","关闭条件":{"fact":"character:witness.dead@world","eq":true},"关闭描述":"赶到时证人已经遇害，此路已断。","后继节点":["question-witness"]}
```

扩展示例（仅增量模式：只传扩展点与新增节点，不得携全量定义改写既有节点；新增节点一律为扩展点的一级后继，不得再带后继节点）：

```json
{"槽位":1,"任务":[{"操作":"扩展","蓝图":{"名称":"账册疑云","扩展点":"follow-up","版本":2,"起始节点":["trace-seal"],"节点":[{"节点ID":"trace-seal","前置节点":["follow-up"],"完成条件":{},"完成摘要":"查到印章来源。","关闭条件":null,"关闭描述":null,"终局":true}]}}]}
```

修改示例（奖励结算被 engine 打回时，修正未完成节点的奖励）：

```json
{"槽位":1,"任务":[{"操作":"修改","蓝图":{"名称":"账册疑云","奖励修改":[{"节点ID":"forged","奖励":{"奖励ID":"ledger:forged:reward","描述":"经验500","状态变更":[{"类型":"经验","操作":"加","角色":"玩家","值":500}]}}]}}]}
```

「修改」只允许改未完成（非已完成/关闭/阻断）节点的奖励；新 `奖励ID` 不得复用已领取或其他节点的 ID；修改后版本自动 +1，同轮 judge 以 `线索-采用草稿.名称列表` 采用，再重新提交触发事实即可继续推进。
