# 大世界游戏规范（强制）

每回合 go/judge 前及输出界面前逐条自检，缺一即修正重做。本文只列强制检查；完整推演机制见 [wuxia-rpg-exploration-rules.md](./wuxia-rpg-exploration-rules.md)，行为参数见 [wuxia-rpg-actions.md](./wuxia-rpg-actions.md)，界面细则见对应 UI 文档。

> **数据红线**：禁止直接修改 `assets/data/`、存档目录或任何数据 JSON。玩家行为经 engine go，普通剧情与状态变化经 plot-writing 暂存、judge 统一提交；其他数据操作使用专用脚本。

## 一、通用时序

- **全程静默**：go、必要判定、plot-writing、草稿准备、judge 与全部自检完成前，不输出说明、草稿、预演或自检过程。
- **先推演后提交**：先预检再 go；无界面时 go 结果仅供推演。完成必要的 check / random-event 后只提交一次 plot-writing，按需各调用一次 scene-prepare / quest-prepare（建议先场景后线索），最后只传 `槽位` 调 judge，由 judge 自动采用全部草稿。已通过校验的阶段不得修改；失败阶段原地修正。即时界面与战斗走各自流程。
- **界面外不思考**：GM 的分析、动机判断和后果预判不得独立输出，只能融入界面内叙事；仅回答元规则时可短暂切出。

## 二、go 前检查

1. **指令归属**：游戏指令必须调 go；日常对话不调。不得以纯叙事代替移动、交谈、调查、战斗、配置或存档结算。
2. **可执行性**：是否先按已确定的剧情/场景约束检查行动？有可执行项则只提交这些 action；全部受阻则传空 `行为` 数组并在后续 judge 叙述原因。成败尚需判定时不得预先判为不可执行。
3. **非法指令**：参数缺失、作弊或不合法需求，是否已走 go「非法指令」并填写提示，而非误用空数组或由 GM 口头拒绝？
4. **位置同步**：玩家实际踏入新场景（含潜入、潜行、赴约）时，是否已用「远行（徒步）」同步当前位置？

## 三、plot-writing / judge 前检查

普通叙事仅 go **没有 `界面` 字段**时走 plot-writing（一次）→ 按需 prepare（各一次）→ judge；有界面直接渲染。剧情与状态变化须基于 go 结果；judge 只传 `槽位` 并自动采用全部草稿。

1. **完整规则**：本轮需要 GM 推演时，是否已整份读取 [wuxia-rpg-exploration-rules.md](./wuxia-rpg-exploration-rules.md)？
2. **判定**：发展是否依赖技艺或一级属性高低？若是，是否先调 `wuxia_check`（不可用时回退 `engine check`），再严格据结果推演？未判直接写定成败即违规。
3. **数据**：铜钱、经验、关系度、物品、装备、队伍、气血内力、体力、位置、武学、生死等变化，是否在 plot-writing 中写成合法状态变更条目？无变化则不传。
4. **场景**：本轮是否新增地点、解锁孤点、隔离或重连路径？若是，是否已在 plot-writing 后一次性批量 `scene-prepare`？草稿由 judge 自动采用。`场景要素`是否非空并描述落定后的场景？新提及且可前往的地点是否都写入 `提及地点`？
5. **线索**：判定与随机结果是否已明确？本轮可追查的未解情报是否当轮建栏？新建/扩展线索是否在 plot-writing 后一次性批量 `quest-prepare`，交由 judge 全部采用？已确认的调查、说服、真伪等结果是否提交对应 `事实`，而非直接改阶段或重传线索栏？
6. **奖励**：是否只在蓝图的阶段成果、关键转折或终局节点配置奖励，并为含状态变更的奖励提供稳定 `奖励ID`？
7. **概括**：`经历概括`是否合并、删除无后续影响的旧内容，而非只增不减？
8. **战斗终局**：是否按胜负完成逐人杀放、逃走者排除、经验分发及 `战斗-结束`？我方胜是否先经 battle-end-ui 收齐玩家决定；我方败/平局是否由 GM 完成敌方处置？分别见 [wuxia-rpg-battle-end-ui.md](./ui/wuxia-rpg-battle-end-ui.md) 与 [wuxia-rpg-battle-ui.md](./ui/wuxia-rpg-battle-ui.md)。

## 四、输出界面前检查

LLM 渲染模式下界面正文由 engine 直出（顶层 `渲染文本`），原样输出、不改写；不带 `渲染文本`（dsh/WEB_UI 模式）时直接输出当前剧情。第 2～4 条由 engine 保证，GM 不再自行拼接核对。

1. **单一界面块**：抬头起、指令提示止；叙事、对话、判定与提示均嵌入，不在界面外加前后说明。
2. **状态提示位置**：置于剧情描写之后、周围情况之前，反引号高亮，一行一条。
3. **结算完整**：逐条核对 judge 返回的最终 `结算`，所有体力、时间、获物、金钱、经验、关系度、线索及自动存档提示均已展示；普通叙事的 go 结果仅供推演，不当作最终结算。
4. **数值来源**：体力、时间、时段、位置、金钱、剩余轮数及队伍气血内力全部取 engine 最新返回，不编造、不沿用旧值。
5. **判定展示**：是否按 [wuxia-rpg-exploration-rules.md](./wuxia-rpg-exploration-rules.md)「判定系统」处理？判定提示不得进入状态变更、`结算`或剧情后的状态提示位。
6. **错误处理**：plot-writing 或 prepare 校验失败时原阶段修正；成功后不得覆盖。judge 失败时保留全部已锁定草稿并重试，不向玩家展示、不重跑 go；message-ui 的 `提示` 才是玩家可见信息。
7. **GM线索提示**：`潜在线索变化`仅用于核对本轮是否应提交事实，`任务扩展`须先 prepare 扩展蓝图；两者都不得向玩家展示或当作已完成进展。

## 五、战斗交互检查

- `battle-ui` / `battle-end-ui` 的 `渲染文本`是否严格原样输出，未润色、截断或重拼？
- 非终局战斗 go 后是否仅调一次 `战斗-推进`，且未传 `战报文本`、未重跑 action？
- 战局终止后是否按胜负完成处决、经验及 `战斗-结束`，而非直接跳回 exploration-ui？

交互路由见 [wuxia-rpg-battle-ui.md](./ui/wuxia-rpg-battle-ui.md) 与 [wuxia-rpg-battle-end-ui.md](./ui/wuxia-rpg-battle-end-ui.md)。
