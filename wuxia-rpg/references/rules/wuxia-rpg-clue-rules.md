# 线索系统

## 一、基本原则

- 玩家界面仍称“线索”；GM 用任务蓝图描述其隐藏结构。
- GM 只提交已经发生并确认的事实，不直接指定“进入某阶段”。
- engine 依据事实自动完成节点、发放奖励、关闭线索并更新线索栏。
- `go` 的 `action.player.completed` 只表示动作已执行；调查成功、说服成立等叙事结果仍须 GM 在 `judge` 中提交事实。
- `任务摘要及进度` 是玩家投影，不是权威状态；不得直接编辑或重传整条线索。

线索生命周期：隐藏 → 进行中 → 已解决 / 已失败 / 已关闭。

## 二、何时创建

信息浮出即入栏，无需玩家接取。一次性情报并入既有线索；可持续推进的委托、冲突或悬案才创建新线索。

即兴线索首次出现时，GM 在本轮判定与随机结果明确后，用 `quest-prepare` 批量预校验所需蓝图，再在同轮 `judge` 以 `任务ID列表` 采用。蓝图至少包含：

- 稳定 `任务ID`、玩家可见名称、引子和隐藏目标；
- 当前核心里程碑与至少一个终局；
- 至少一个玩家可执行的当前方向；
- 条件所需的事实定义；
- 各可见节点的完成摘要；
- 稳定奖励 ID，或明确无奖励。

未来不确定内容可留为显式扩展点，但不得留下无后继、无终局、非扩展点的断头节点。`quest-prepare` 不创建正式线索、不改事实或奖励；失败可修正后重试，只有最终 `judge` 成功才生效。

## 三、事实规则

事实键格式：

```text
<subject-id>.<predicate>@<scope>
```

示例：

```text
item:ledger_001.authenticity@world
item:ledger_001.authenticity@character:掌柜
location:旧宅.accessible@world
```

- 客观真相、NPC 说法、传闻和角色认知必须使用不同 scope，不得混写。
- 已确认事实冲突时，普通 `事实` 写入会被拒绝；确需揭示误认、调包或设定修订时，用 `事实-修订` 并写明原因。
- 已有世界真相优先于新蓝图。蓝图与既有事实矛盾时，修改蓝图，不得让 engine 静默选择某条线索。
- 枚举事实的每个合法结果都须通向终局或显式扩展点。

## 四、推进与扩展

### 推进

剧情确认了任务语义结果时，在 `judge.行为` 中提交 `事实`。engine 会同步归约所有引用该事实的线索。

机械事实（时间、体力、位置、持有物、关系度、生死等）由既有状态变更事件自动维护；GM 不重复写。

节点完成后：

1. engine 记录稳定节点 ID；
2. 同批执行节点效果与奖励；
3. 全部成功提交后，线索栏才显示完成摘要；
4. 任一奖励或触发失败，则节点、奖励和摘要一并不提交。

已完成节点和已领取奖励不会因后续事实修订而撤销。

### 扩展

进入扩展点前，GM 必须在 `quest-prepare.任务` 中加入“扩展”项，再在同轮 `judge` 以任务 ID 采用：

- 指定原 `任务ID` 和 `扩展点`；
- 版本递增；
- 只新增后续节点和必要事实定义；
- 不得删除或改写已完成节点、历史摘要和已领取奖励。

## 五、节点与奖励

完成摘要只写玩家已经获知的客观进展，不剧透隐藏目标、未满足条件或预设结局。只有实质进展才设可见节点：新情报、关键转折、阶段成果、明确下一步或终局。

经验参考：

- 过渡/小节点：200～600
- 常规节点：800～1500
- 关键节点：1800～3000
- 解决/关闭节点：3000～5000

奖励随节点一次性结算；含状态变更的奖励必须提供稳定 `奖励ID`。自然移动、寒暄、重复确认和无成果的失败判定不发奖励。

## 六、GM 提示

engine 返回 `GM线索提示` 时：

- `潜在线索变化`：本轮动作可能对应某个未确认事实；只有剧情确已成立时才在 `judge` 提交。
- `任务扩展`：线索已抵达扩展前沿，须先用 `quest-prepare` 准备扩展，再由 `judge` 采用。

这些提示仅供 GM 使用，不得直接展示给玩家，也不得当作已经完成的线索进展。

具体 JSON 契约见 [wuxia-rpg-actions.md](../wuxia-rpg-actions.md)。
